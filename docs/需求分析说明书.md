# 需求分析说明书

## 1. 文档目的

本文档用于说明“线槽拖链选型”项目的业务背景、用户目标、业务流程、数据需求、功能范围和约束条件。内容依据当前代码实现编写，覆盖前端 `DragChain.Client`、后端 `DragChain.API`、SQLite 数据库和 IIS 发布脚本。

## 2. 项目概述

本项目是一个面向内网使用的线槽与拖链选型计算工具，用于根据管线清单、运动参数、型录数据和有效利用率规则，自动计算并推荐线槽或拖链型号。

系统采用前后端分离开发、同站点部署的方式：

- 前端：Vue 3、Vite、TypeScript、Element Plus、Pinia、Vue Router。
- 后端：ASP.NET Core 8 Web API、Entity Framework Core、SQLite。
- 部署：前端构建产物复制到后端 `wwwroot`，由后端应用在 IIS 同一站点、同一端口托管。
- 数据库：默认 SQLite 文件 `dragchain.db`，启动时自动迁移并补齐兼容字段。

## 3. 业务背景

设备设计和电气设计过程中，需要根据实际管线、气管、电缆、编码器线、运动行程和拖链品牌规则选择合适的拖链，也需要根据强弱电管线面积选择左右线槽规格。人工计算容易出现以下问题：

- 管线数量、直径、重量和弯曲半径核算重复繁琐。
- WZL 与 ME 拖链型录字段不同，选择规则不同。
- 强弱电线槽需要分侧计算，人工拆分容易遗漏。
- 线槽有效利用率上限需要可调整并长期保存。
- 管线和型录数据需要在内网环境中可维护。

因此系统需要提供一个可维护、可部署、可复核计算过程的选型工具。

## 4. 用户角色

### 4.1 选型使用人员

主要使用“线槽选型”和“拖链选型”页面，输入管线清单、运动参数、有效利用率等数据，查看推荐结果和计算过程。

### 4.2 数据维护人员

维护管线库、模块库、WZL 型录、ME 型录、线槽型录。可新增、编辑、删除基础数据。

### 4.3 部署维护人员

负责在 Windows IIS 服务器上部署发布包，维护应用程序池、站点绑定、数据库文件和运行目录。

## 5. 使用场景

### 5.1 线槽选型

用户进入线槽选型页面，设置有效利用率上限，从管线库或模块库添加管线，系统自动按强弱电分侧计算推荐线槽。

当前实现特点：

- 线槽页面不允许选择气管。
- 线槽页面允许弱电电缆、强电电缆、编码器线参与计算。
- 强电电缆进入右侧强电线槽。
- 弱电电缆、编码器线及其他非强电类型进入左侧弱电线槽。
- 有效利用率上限保存到数据库 `AppSettings`。

### 5.2 拖链选型

用户进入拖链选型页面，选择品牌 WZL 或 ME，输入感应器个数、非同动气缸磁环组数、运动方式、移动行程、固定端偏移 Lm，并从管线库或模块库添加管线。系统自动计算最小内高、弯曲半径、内空面积、架空能力和最终推荐型号。

当前实现特点：

- 拖链页面可以选择所有管线类型，包括气管。
- 支持品牌：沃德无尘拖链 WZL、犸幕普通拖链 ME。
- 支持运动方式：横移、升降。
- 升降模式无架空长度需求，最终结论按初步选型给出提示。

### 5.3 管线库维护

用户维护管线名称、分类、直径、重量、弯曲倍数。系统用于线槽和拖链计算。

当前支持分类：

- 气管：`tube`
- 弱电电缆：`weak_cable`
- 强电电缆：`strong_cable`
- 编码器线：`encoder`
- 其他：`other`
- 历史兼容类型：`cable` 显示为弱电电缆。

### 5.4 模块库维护

用户将多条管线组合成模块，例如阀岛模块、标准伺服包。模块可在选型页面一次加入，并按模块数量展开为真实管线数量参与计算。

### 5.5 型录维护

用户可维护：

- WZL 拖链型录。
- ME 拖链型录。
- 线槽型录。

型录数据供计算服务匹配推荐结果使用。

## 6. 业务流程

### 6.1 线槽选型流程

1. 用户进入 `/trunking/calc`。
2. 前端读取有效利用率设置：`GET /api/trunking/settings`。
3. 前端读取管线库和模块库。
4. 用户调整有效利用率上限，前端防抖后保存：`PUT /api/trunking/settings`。
5. 用户点击“新增管线”，弹窗展示允许用于线槽的管线和模块。
6. 用户选择管线或模块并加入清单。
7. 前端将模块展开为管线清单。
8. 前端请求线槽计算：`POST /api/trunking/calc`。
9. 后端过滤气管，按强弱电分侧计算面积、有效利用率、推荐线槽。
10. 前端展示实际有效利用率、左右侧推荐线槽和匹配列表。

### 6.2 拖链选型流程

1. 用户进入 `/chain/calc`。
2. 前端读取管线库和模块库。
3. 用户选择品牌、输入芯数相关数量、运动参数。
4. 用户从管线库或模块库加入管线清单。
5. 前端将模块展开为真实管线数量。
6. 前端请求拖链计算：`POST /api/Calculation/calc`。
7. 后端按品牌执行 WZL 或 ME 计算逻辑。
8. 前端展示型号匹配矩阵、计算过程明细、核算指标和最终结论。

### 6.3 基础数据维护流程

1. 用户进入相应维护页面。
2. 前端调用列表接口读取数据。
3. 用户新增、编辑或删除记录。
4. 后端写入 SQLite。
5. 前端刷新列表。

## 7. 数据需求

系统需要持久化以下数据：

- 管线类型：名称、分类、直径、重量、弯曲倍数。
- 管线模块：模块名称、说明、包含的管线和数量。
- WZL 型录：型号、功能、行程、内外尺寸、弯曲半径、弯曲长度、安装高度、内空面积、适用管线。
- ME 型录：基础型号、功能选择、内高内宽、R1/R2/R3、后缀、LP、安装高度、内部面积、最大重量、架空参数。
- 线槽型录：型号、宽、高、截面积。
- 应用设置：线槽有效利用率上限。

系统不持久化当前选型页面的临时输入，如当前管线清单、移动行程、品牌选择、计算结果。

## 8. 功能范围

### 8.1 范围内

- 线槽选型计算。
- 拖链选型计算。
- 管线库 CRUD。
- 模块库 CRUD。
- WZL 型录 CRUD。
- ME 型录 CRUD。
- 线槽型录 CRUD。
- 线槽有效利用率上限保存。
- 默认型录和管线种子数据初始化。
- SQLite 结构迁移和部分旧库兼容。
- IIS 单站点发布脚本。

### 8.2 范围外

当前代码未实现以下能力：

- 用户登录、角色权限和审计日志。
- 多人协同编辑冲突处理。
- 计算结果历史保存。
- Excel 导入导出。
- 管线清单模板持久化。
- 多数据库支持。
- 外部接口集成。

## 9. 非功能需求

### 9.1 部署要求

- 支持 Windows + IIS 部署。
- 前端和后端发布为同一个 IIS 站点。
- 对外端口由 IIS 站点绑定决定。
- 应用程序池建议使用“无托管代码”。
- 需要安装 .NET 8 Hosting Bundle。

### 9.2 性能要求

当前数据规模以型录表和管线库小规模内网使用为主。计算逻辑以内存加载型录后遍历匹配为主，适用于几十到几百条型录记录。

### 9.3 可维护性要求

- 型录和管线数据通过页面维护。
- 计算规则集中在后端服务，前端主要负责输入、展示和调用 API。
- 发布脚本统一生成 IIS 发布文件。

### 9.4 可靠性要求

- 后端启动时执行 EF Core 迁移。
- 对旧 SQLite 结构执行兼容修复。
- 发布脚本移除发布包中的运行期数据库和日志，避免覆盖目标环境数据。

### 9.5 安全边界

当前系统按内网工具设计，未实现登录鉴权。部署时应通过 IIS、内网访问控制或服务器网络策略限制访问范围。

## 10. 主要约束

- 默认数据库为 SQLite 文件。
- 前端生产环境默认走同源 `/api`，开发环境默认 API 地址为 `http://localhost:5256/api`。
- 同站点部署依赖后端 `wwwroot` 托管前端构建产物。
- 线槽计算后端会过滤气管；前端线槽页面也不展示气管。
- 各控制器的 `reset` 当前调用统一重置逻辑，会重置管线库、WZL、ME、线槽型录。

## 11. 风险与注意事项

- 删除管线时，如果管线被模块引用，后端会拒绝删除。
- 型录删除后可能导致选型无可用型号。
- 有效利用率上限保存为 0 到 1 之间的小数，前端显示为百分比。
- SQLite 数据库文件应在部署环境中妥善备份。
- 发布脚本生成的发布目录不包含运行期数据库，避免误覆盖生产数据。
