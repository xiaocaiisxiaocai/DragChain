# 功能设计说明书

## 1. 文档目的

本文档描述“线槽拖链选型”系统的功能结构、页面设计、接口设计、核心计算逻辑、部署设计和错误处理方式。内容以当前项目代码为准。

## 2. 总体架构

系统采用前后端分离开发、后端同站点托管前端的结构。

```text
浏览器
  |
  | HTTP
  v
IIS 站点 / ASP.NET Core 应用
  |
  |-- 静态文件: wwwroot/index.html, assets
  |-- Web API: /api/*
  |
  v
SQLite 数据库 dragchain.db
```

开发环境：

- 前端 Vite 运行在 `5173`。
- 前端 `/api` 代理到后端 `5256`。
- 后端提供 Swagger、API 和数据库访问。

生产环境：

- 通过 `scripts/publish-iis.ps1` 构建发布。
- 前端构建产物复制到 `DragChain.API/wwwroot`。
- `dotnet publish` 生成 IIS 发布目录。
- IIS 只绑定一个站点和一个端口。

### 4.4 管线选择弹窗

文件：`DragChain.Client/src/components/AddPipeDialog.vue`

功能：

- 支持从管线库选择单条管线。
- 支持从模块库选择模块。
- 已在当前清单中的项目禁用。
- 按分类分组展示管线。
- 空分组不展示。
- 支持 `allowedTypes` 限制可选类型。

分类顺序：

1. 气管
2. 弱电电缆
3. 强电电缆
4. 编码器线
5. 其他

线槽页面传入：

```ts
const TRUNKING_ALLOWED_TYPES = ['weak_cable', 'strong_cable', 'encoder'];
```

因此线槽页面不会显示气管。

### 4.5 模块展开设计

文件：`DragChain.Client/src/utils/pipeSelection.ts`

功能：

- 将前端清单中的单条管线和模块统一展开为后端计算需要的 `{ pipeTypeId, qty }[]`。
- 同一管线 ID 的数量合并。
- 模块数量乘以模块内单项数量。
- 无效 ID 或非正数量会被忽略。

### 4.6 清单展示设计

文件：`DragChain.Client/src/utils/trunkingSelectionDisplay.ts`

功能：

- 将管线清单转换为表格行。
- 支持模块展开子行。
- 显示管线名称、类型、左右侧、数量、尺寸和面积。
- 支持两种面积模式：
  - `square`：线槽使用，面积为 `直径 × 直径 × 数量`。
  - `circle`：拖链使用，面积为 `π × (直径 / 2)^2 × 数量`。

## 5. 线槽选型功能设计

### 5.1 页面结构

文件：`DragChain.Client/src/views/TrunkingCalcView.vue`

页面区域：

- 选型参数：填充率上限。
- 管线清单：线槽可用管线和模块。
- 填充率核算：实际填充率、进度条、结论。
- 左侧弱电线槽结果。
- 右侧强电线槽结果。

### 5.2 前端状态

| 状态 | 说明 |
| --- | --- |
| `fillRatio` | 前端百分比，默认 `75` |
| `activePipes` | 当前页面临时管线清单 |
| `result` | 后端线槽计算响应 |
| `loading` | 计算加载状态 |
| `settingsLoading` | 设置读取状态 |
| `settingsSaving` | 设置保存状态 |
| `settingsSaved` | 保存成功提示状态 |

### 5.3 前端过滤

线槽页面通过 `isTrunkingPipe` 统一判断管线是否适用于线槽：

- 使用 `getPipeDisplayType` 处理历史 `cable` 类型。
- 允许弱电、强电、编码器。
- 排除气管。

模块也会过滤：

- 只保留模块内适用于线槽的管线项。
- 如果模块过滤后没有任何管线，则不展示该模块。

### 5.4 自动计算

触发条件：

- 管线清单变化。
- 填充率变化。

处理方式：

- 管线清单变化后防抖 300ms 计算。
- 填充率变化后防抖 300ms 计算，并防抖 600ms 保存设置。

### 5.5 后端接口

控制器：`DragChain.API/Controllers/TrunkingController.cs`

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/trunking` | 获取线槽型录 |
| POST | `/api/trunking` | 新增线槽型录 |
| PUT | `/api/trunking/{id}` | 更新线槽型录 |
| DELETE | `/api/trunking/{id}` | 删除线槽型录 |
| POST | `/api/trunking/calc` | 线槽计算 |
| GET | `/api/trunking/settings` | 获取填充率设置 |
| PUT | `/api/trunking/settings` | 保存填充率设置 |
| POST | `/api/trunking/reset` | 重置默认数据 |

### 5.6 后端计算

服务：`DragChain.API/Services/TrunkingCalculationService.cs`

流程：

1. 加载全部管线，按 ID 建立映射。
2. 过滤无效管线和数量。
3. 后端再次过滤气管。
4. 校验填充率，非法时使用默认 `0.75`。
5. 加载线槽型录并按截面积排序。
6. 将管线分为弱电侧和强电侧。
7. 分别计算弱电和强电推荐线槽。
8. 汇总整体状态和步骤。

分侧规则：

- `strong_cable` 为强电侧。
- 其他非气管类型为弱电侧。

面积规则：

```text
单侧管线面积 = Σ(管线直径 × 管线直径 × 数量)
所需线槽面积 = 单侧管线面积 / 填充率上限
实际填充率 = 单侧管线面积 / 选中线槽面积
```

推荐规则：

- 选取截面积大于等于所需线槽面积的最小线槽。
- 若没有满足项，则选取最大线槽并标记超限。
- 无管线时单侧状态为 `ok`，消息为“无管线”。

- 移动行程变化。

| 方法 | 路径 | 功能 |
| --- | --- | --- |

### 6.5 通用计算规则

服务：`DragChain.API/Services/CalculationService.cs`

通用公式：

```text
芯数 = 感应器个数 + ceil(感应器个数 / 3) × 2 + ceil(磁环组数 / 3) × 2 + 2
管线总面积 = Σ(π × (直径 / 2)^2 × 数量)
总重量 = Σ(重量 × 数量)
最大管线外径 = max(直径)
最小内高 = 最大管线外径 × 1.25
最小弯曲半径 = max(气管弯曲半径, 电缆弯曲半径, 编码器线弯曲半径)
横移需要架空长度 = 移动行程 / 2
升降需要架空长度 = 0
```

弯曲半径：

```text
单条管线弯曲半径 = 直径 × 弯曲倍数
气管、编码器线、电缆分别取最大值
```

内空占比：

- WZL：`60%`
- ME：`55%`

最小内部面积：

```text
最小内部面积 = 管线总面积 / 内空占比
```

拖链长度：

```text
Lk = ceil((移动行程 / 2 + Lm + Lp) / 10) × 10
```

### 6.6 WZL 计算设计

参与计算数据：

- `WzlCatalog`
- 仅 `Function = "S:標準款"` 且 `InnerArea != null` 的记录参与选型。
- WZL 架空参数来自 `CatalogSeeder.GetDefaults().wzlSpanData`。

初判条件：

```text
最小内高 <= 型号内高
最小弯曲半径 <= 推荐 R
最小内部面积 <= 型号内空面积
```

架空能力：

```text
如果总重量 > 最大重量，则架空能力 = 0
否则架空能力 = max(0, spanBase - spanSlope × 总重量)
```

特殊规则：

- `WZL15.025.02` 在有架空需求时永远 NG。
- 升降模式不做最终架空匹配，存在初判型号时返回警告结论。

最终判定：

```text
最终满足 = 初判满足 && 架空满足
```

### 6.7 ME 计算设计

参与计算数据：

- `MeCatalog`
- 每条记录展开为 R1、R2、R3 三个候选。

候选型号：

```text
候选型号 = BaseModel + 对应 R 后缀
```

初判条件：

```text
最小内高 <= InnerHeight
最小弯曲半径 <= 当前 R
最小内部面积 <= InnerArea
```

架空能力：

```text
如果总重量 > MaxWeight，则架空能力 = 0
否则架空能力 = max(0, SpanBase - SpanSlope × 总重量)
```

最终判定：

```text
横移: 初判满足 && 架空能力 > 需要架空长度
升降: 不做最终架空匹配，存在初判型号时返回警告结论
```

- 后端校验模块内管线 ID 是否存在。
- 后端按 `PipeTypeId` 合并重复项数量。

- `WzlCatalogView.vue`

## 8. 后端启动设计

文件：`DragChain.API/Program.cs`

启动流程：

1. 读取连接字符串，默认 `Data Source=dragchain.db`。
2. 注册 EF Core SQLite DbContext。
3. 注册拖链计算服务和线槽计算服务。
4. 注册 CORS、Controller、Swagger。
5. 应用启动后创建作用域。
6. 执行 `context.Database.Migrate()`。
7. 执行 `SqliteSchemaCompatibility.EnsureAsync(context)`。
8. 执行 `CatalogSeeder.SeedAsync(context)`。
9. 启用 CORS。
10. 启用默认文件和静态文件。
11. 启用 Swagger。
12. 映射 Controller、健康检查和前端路由回退。

## 9. 数据初始化和兼容设计

初始化服务：`CatalogSeeder.cs`

启动时：

- 删除类型为 `water` 或名称包含“水管”的管线。
- 管线表为空时写入默认管线。
- 管线表不为空时标准化旧分类。
- WZL 表为空时写入默认 WZL 型录。
- ME 表为空时写入默认 ME 型录。
- 线槽表为空时写入默认线槽型录。

兼容服务：`SqliteSchemaCompatibility.cs`

兼容内容：

- 为旧 `MeCatalog` 补充 `FunctionSelect` 字段。
- 为旧 `MeCatalog` 补充 `MountingH1` 字段。
- 如果旧 `TrunkingCatalog` 存在历史字段，重建表为当前结构。

## 10. 发布设计

脚本：`scripts/publish-iis.ps1`

默认流程：

1. 设置发布配置，默认 `Release`。
2. 设置输出目录，默认 `publish/iis-dragchain`。
3. 执行前端构建：`npm run build`。
4. 删除并重建后端 `wwwroot`。
5. 复制前端 `dist` 到后端 `wwwroot`。
6. 删除旧发布目录。
7. 执行 `dotnet publish`。
8. 删除发布目录中的运行期数据库和日志文件。
9. 输出 IIS 部署提示。

IIS 配置：

- 站点物理路径指向发布目录。
- 应用程序池设置为“无托管代码”。
- 对外端口由 IIS 站点绑定决定。

## 11. 错误处理设计

### 11.1 前端

- API 非 2xx 响应抛出异常。
- 页面捕获异常后显示错误消息或 Element Plus 提示。
- 删除操作前使用确认弹窗。
- 保存成功后使用消息提示。

### 11.2 后端

- 找不到记录返回 `404`。
- 删除被模块引用的管线返回 `409 Conflict`。
- 填充率非法返回 `400 BadRequest`。
- 模块内容非法返回 `400 BadRequest`。

## 12. 当前限制

- 没有登录和权限控制。
- 没有计算结果保存。
- 没有导入导出。
- 各型录重置接口实际调用统一重置逻辑，会重置多类基础数据。
- 部分业务规则写在代码中，例如 WZL 架空参数和 WZL15 特殊规则。
- 前端页面临时清单刷新后会丢失。
