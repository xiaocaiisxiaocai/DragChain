# 需求规格说明书

## 1. 文档目的

本文档定义“选型软件”的功能性需求、接口需求、数据需求、权限需求、非功能需求和验收标准。内容基于当前代码实现，不包含尚未实现的规划功能。

## 2. 系统范围

系统提供以下功能域：

- 线槽选型。
- 拖链选型。
- 感应器选型。
- 感应器产品管理。
- 用户登录和角色权限管理。
- 管线库维护。
- 模块库维护。
- WZL 型录维护。
- ME 型录维护。
- 线槽型录维护。
- 线槽有效利用率设置。
- IIS 单站点发布。

除登录、Token 刷新和健康检查外，线槽、拖链、管线库、型录及感应器等业务 API 均需要登录，并按 RBAC 校验页面和接口权限；只读接口同样纳入认证范围。

## 3. 运行环境规格

### 3.1 客户端

- 浏览器：现代 Chromium、Edge 或同等支持 ES Module 的浏览器。
- 访问方式：浏览器访问 IIS 站点地址。

### 3.2 服务端

- 操作系统：Windows Server 或 Windows 桌面系统。
- Web 服务器：IIS。
- 运行时：.NET 8 ASP.NET Core Hosting Bundle。
- 数据库：SQLite。

### 3.3 开发环境

- 前端开发端口：`5173`。
- 后端开发 API 默认地址：`http://localhost:5256/api`。
- Vite 代理：`/api` 转发到 `http://localhost:5256`。

### 3.4 生产环境

- 前端静态文件由后端 `wwwroot` 托管。
- API 与前端同源。
- 端口由 IIS 站点绑定决定。

## 4. 术语定义

| 术语 | 定义 |
| --- | --- |
| 管线 | 参与线槽或拖链选型的电缆、气管、编码器线等对象。 |
| 模块 | 多条管线按固定数量组合形成的复用清单。 |
| WZL | 沃德无尘拖链品牌/系列。 |
| ME | 犸幕普通拖链品牌/系列。 |
| 有效利用率 | 按 `直径 × 直径` 包络面积计算的管线占用面积与线槽截面积的比例。 |
| 架空能力 | 拖链在给定负载下可满足的架空长度。 |
| Lp | 拖链弯曲长度。 |
| Lk | 拖链选定长度。 |
| Lm | 拖链固定端偏移中心点距离。 |

## 5. 功能性需求

### FR-001 线槽选型入口

系统应提供线槽选型页面，路由为 `/trunking/calc`。

验收标准：

- 用户进入根路径 `/` 时默认跳转到 `/trunking/calc`。
- 页面显示有效利用率上限、管线清单、有效利用率核算、左右侧线槽结果。

### FR-002 线槽有效利用率上限读取

系统应在进入线槽选型页面时读取数据库中的有效利用率上限。

接口：

- `GET /api/trunking/settings`

验收标准：

- 如果数据库存在 `TrunkingFillRatioLimit`，返回该值。
- 如果不存在或值非法，返回默认值 `0.60`。
- 前端以百分比形式显示，例如 `60%`。

### FR-003 线槽有效利用率上限保存

系统应支持修改线槽有效利用率上限并保存到数据库。

接口：

- `PUT /api/trunking/settings`

输入：

```json
{
  "fillRatio": 0.60
}
```

验收标准：

- 仅允许大于 `0` 且不超过 `1` 的小数。
- 保存成功后返回保存值。
- 前端输入变化后防抖保存。
- 保存过程中显示“保存中”，保存成功显示“已保存”。

### FR-004 线槽管线选择

系统应支持从管线库和模块库向线槽清单新增项目。

验收标准：

- 弹窗显示“管线”和“模块”两个页签。
- 已加入当前清单的管线或模块自动禁用。
- 线槽场景不显示气管。
- 线槽场景仅显示弱电电缆、强电电缆、编码器线。
- 空分组不显示标题。
- 模块在加入前应过滤掉不适用于线槽的管线项。

### FR-005 线槽管线清单维护

系统应支持线槽页面临时维护管线清单。

验收标准：

- 支持调整管线或模块数量。
- 支持删除清单项。
- 模块项可展开展示子管线。
- 当前清单不保存到数据库。

### FR-006 线槽计算

系统应根据管线清单、线槽型录和有效利用率上限计算推荐线槽。

接口：

- `POST /api/trunking/calc`

核心规则：

- 后端忽略气管。
- 强电电缆进入强电侧。
- 非强电电缆进入弱电侧。
- 单侧管线面积按 `直径 × 直径 × 数量` 计算。
- 推荐线槽为截面积满足 `管线面积 / 有效利用率上限` 的最小线槽。
- 如果没有满足线槽，取最大线槽并返回超限状态。

验收标准：

- 返回总面积、最大管径、总根数、实际有效利用率。
- 返回弱电侧、强电侧各自结果。
- 返回每个线槽型号的有效利用率和是否推荐。
- 型录为空时返回错误状态。

### FR-007 拖链选型入口

系统应提供拖链选型页面，路由为 `/chain/calc`。

验收标准：

- 页面支持选择 WZL 或 ME。
- 页面支持输入感应器个数、非同动气缸磁环组数、运动方式、移动行程、固定端偏移。
- 页面支持添加管线和模块。
- 页面展示匹配矩阵、计算过程、核算指标和结论。

### FR-008 拖链管线选择

系统应支持拖链页面选择全部管线类型。

验收标准：

- 拖链页面可选择气管、弱电电缆、强电电缆、编码器线、其他。
- 可选择模块。
- 模块按模块数量展开参与计算。

### FR-009 拖链计算

系统应根据品牌、运动参数和管线清单执行拖链选型。

接口：

- `POST /api/Calculation/calc`

核心规则：

- 芯数公式：`感应器个数 + ceil(感应器个数 / 3) × 2 + ceil(磁环组数 / 3) × 2 + 2`。
- 管线圆形面积：`π × (直径 / 2)^2 × 数量`。
- 总重量：`重量 × 数量` 求和。
- 最小内高：`最大管线外径 × 1.25`。
- WZL 内空占比：`60%`。
- ME 内空占比：`55%`。
- 最小内部面积：`管线总面积 / 内空占比`。
- 横移需要架空长度：`移动行程 / 2`。
- 升降需要架空长度：`0`。
- 拖链长度：`ceil((移动行程 / 2 + Lm + Lp) / 10) × 10`。

验收标准：

- 无管线时返回警告状态和空步骤。
- 有管线时返回匹配矩阵。
- 返回初步选型和最终选型。
- 升降模式存在初步选型时返回警告状态并提示无需架空判定。
- 无合适型号时返回错误状态和处理建议。

### FR-010 WZL 拖链计算

系统应支持 WZL 型录计算。

核心规则：

- 只使用 `Function = "S:標準款"` 且 `InnerArea` 不为空的 WZL 型录参与选型。
- 初判条件：内高、推荐弯曲半径、内空面积均满足。
- 架空能力来自内置 WZL 架空参数。
- 重量超过最大重量时架空能力为 `0`。
- `WZL15.025.02` 在有架空需求时按 NG 处理。

验收标准：

- 返回每个 WZL 型号的 `OK/NG` 判定。
- 返回最终型号和 Lk。

### FR-011 ME 拖链计算

系统应支持 ME 型录计算。

核心规则：

- 每条 ME 型录展开为 R1、R2、R3 三个候选。
- 候选型号由基础型号和对应后缀组成。
- 初判条件：内高、弯曲半径、内部面积均满足。
- 架空能力：`SpanBase - SpanSlope × 总重量`，重量超过最大重量时为 `0`。
- 横移时架空能力需大于需要架空长度。

验收标准：

- 返回每个 ME 候选型号的 `OK/NG` 判定。
- 返回最终型号和 Lk。

### FR-012 管线库管理

系统应提供管线库页面，路由为 `/pipe-library`。

接口：

- `GET /api/PipeLibrary`
- `POST /api/PipeLibrary`
- `PUT /api/PipeLibrary/{id}`
- `DELETE /api/PipeLibrary/{id}`
- `POST /api/PipeLibrary/reset`

验收标准：

- 支持搜索。
- 支持新增、编辑、删除。
- 删除被模块引用的管线时返回冲突错误。
- 管线分类应标准化保存。

### FR-013 模块库管理

系统应提供模块库页面，路由为 `/pipe-modules`。

接口：

- `GET /api/PipeModules`
- `GET /api/PipeModules/{id}`
- `POST /api/PipeModules`
- `PUT /api/PipeModules/{id}`
- `DELETE /api/PipeModules/{id}`

验收标准：

- 支持搜索模块名称、说明和包含内容。
- 支持展开查看模块内管线。
- 新增和编辑时模块必须有名称。
- 模块至少包含一条有效管线。
- 重复管线按管线 ID 合并数量。

### FR-014 WZL 型录管理

系统应提供 WZL 型录页面，路由为 `/chain/wzl`。

接口：

- `POST /api/Wzl`

验收标准：

### FR-015 ME 型录管理

系统应提供 ME 型录页面，路由为 `/chain/me`。

接口：

- `GET /api/Me`
- `POST /api/Me`
- `PUT /api/Me/{id}`
- `DELETE /api/Me/{id}`

验收标准：

- 支持维护基础型号、功能选择、内高内宽、R1/R2/R3、后缀、LP、安装高度、内部面积、最大重量、架空基准和架空斜率。

系统应提供健康检查接口。

接口：

## 6. 数据规格

### 6.1 管线分类

| 值 | 含义 | 线槽可选 | 拖链可选 |
| --- | --- | --- | --- |
| `tube` | 气管 | 否 | 是 |
| `weak_cable` | 弱电电缆 | 是 | 是 |
| `strong_cable` | 强电电缆 | 是 | 是 |
| `encoder` | 编码器线 | 是 | 是 |
| `other` | 其他 | 当前前端线槽不展示 | 是 |
| `cable` | 历史兼容弱电电缆 | 兼容为弱电 | 兼容为弱电 |

### 6.2 状态值

计算接口返回状态：

- `ok`：满足要求。
- `warn`：可给出参考结果但存在提示。
- `err`：无合适型号或计算不满足要求。

## 7. 接口通用规格

### 7.1 JSON 格式

后端 JSON 属性使用 camelCase。

### 7.2 错误格式

当前前端按响应文本处理错误，格式为：

```text
API Error {status}: {responseText}
```

### 7.3 204 响应

更新和删除接口可返回 `204 No Content`，前端将其作为成功处理。

## 8. 非功能需求

### NFR-001 易部署

系统应提供脚本生成 IIS 发布文件。

脚本：

```powershell
scripts/publish-iis.ps1
```

验收标准：

- 默认生成到 `publish/iis-dragchain`。
- 自动构建前端。
- 自动复制前端构建产物到后端 `wwwroot`。
- 自动执行 `dotnet publish`。
- 发布目录不包含运行期数据库和日志。

### NFR-002 内网访问与身份权限

系统面向内网部署，但内网边界不能替代应用认证。除明确公开的端点外，业务 API 必须使用签名 Bearer Token 并通过 RBAC 授权。

验收标准：

- 同站点部署后不需要 CORS。
- 开发环境保留 CORS 和 Vite 代理兼容。
- 无需 Bearer Token 的端点仅包括 `OPTIONS /api/*`、`GET /api/health`、`POST /login`（兼容别名 `POST /api/auth/login`）和 `POST /refresh-token`（兼容别名 `POST /api/auth/refresh-token`）；登录需要有效工号和密码，刷新需要有效 Refresh Token。
- 其他 `/api/*` 请求未登录时返回 `401`，权限不足时返回 `403`。
- `super_admin` 和 `admin` 具备完整权限，`editor` 不具备 RBAC 写权限，普通角色默认仅具备选型及基础数据读取权限。
- 生产环境必须安全注入至少 32 字节高熵的 `DRAGCHAIN_AUTH_SIGNING_KEY`，不得将值写入仓库、发布包或日志。
- 新建空 `sensor.db` 首次启动必须显式设置至少 12 个字符且包含字母、数字和符号的 `DRAGCHAIN_BOOTSTRAP_ADMIN_PASSWORD`；可选使用 `DRAGCHAIN_BOOTSTRAP_ADMIN_EMPLOYEE_NO` 指定初始化管理员工号，不得提供固定默认密码。升级含历史固定账号的旧库时，若不存在已启用的非旧版超级管理员，也必须提供该强密码完成一次性轮换，否则应用拒绝启动；已有安全超级管理员时应自动禁用旧账号并销毁其原凭据。

### NFR-003 数据持久化

系统应通过 SQLite 保存基础数据和设置。

验收标准：

- 应用启动时执行迁移。
- 自动补齐历史字段兼容。
- 种子数据只在对应表为空时初始化。

### NFR-004 可维护性

系统应尽量将计算规则放在后端。

验收标准：

- 拖链计算集中在 `CalculationService`。
- 线槽计算集中在 `TrunkingCalculationService`。
- 前端仅做输入、展示、模块展开和 API 调用。
