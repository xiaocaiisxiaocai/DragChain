# 数据库设计说明书

## 1. 文档目的

本文档说明“线槽拖链选型”系统的数据库设计，包括数据库类型、连接方式、实体表、字段、索引、关系、初始化、迁移和数据约束。内容依据当前 `DragChain.API` 代码编写。

## 2. 数据库概述

数据库采用 SQLite，通过 Entity Framework Core 访问。

默认连接字符串：

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=dragchain.db"
  }
}
```

DbContext：

```text
DragChain.API/Data/DragChainDbContext.cs
```

数据库文件：

```text
dragchain.db
```

发布脚本会从发布包中移除运行期数据库文件，避免部署时覆盖目标环境数据。

## 3. 表清单

| 表名 | 实体 | 说明 |
| --- | --- | --- |
| `PipeTypes` | `PipeType` | 管线库 |
| `PipeModules` | `PipeModule` | 管线模块主表 |
| `PipeModuleItems` | `PipeModuleItem` | 管线模块明细 |
| `WzlCatalog` | `WzlCatalog` | 沃德 WZL 拖链型录 |
| `MeCatalog` | `MeCatalog` | 犸幕 ME 拖链型录 |
| `TrunkingCatalog` | `TrunkingCatalog` | 线槽型录 |
| `AppSettings` | `AppSetting` | 应用设置 |

## 4. ER 关系

```text
PipeTypes 1 ---- n PipeModuleItems n ---- 1 PipeModules

WzlCatalog          独立型录表
MeCatalog           独立型录表
TrunkingCatalog     独立型录表
AppSettings         独立键值设置表
```

关系说明：

- 一个模块 `PipeModules` 可以包含多条模块明细 `PipeModuleItems`。
- 一条模块明细引用一个管线 `PipeTypes`。
- 删除模块时级联删除模块明细。
- 删除管线时数据库关系为限制删除，控制器也会检查是否被模块引用。

## 5. 表结构设计

### 5.1 PipeTypes

用途：保存管线库基础数据，供拖链和线槽计算使用。

实体文件：

```text
DragChain.API/Models/PipeType.cs
```

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 管线 ID |
| `Name` | `TEXT` | 必填，最大 200 | 管线名称 |
| `Type` | `TEXT` | 必填，最大 20 | 管线分类 |
| `Diameter` | `decimal(8,2)` | 非空 | 直径，单位 mm |
| `Weight` | `decimal(10,4)` | 非空 | 重量，单位 kg/m |
| `BendMultiplier` | `INTEGER` | 非空，默认 8 | 弯曲倍数 |

分类取值：

| 值 | 含义 |
| --- | --- |
| `tube` | 气管 |
| `weak_cable` | 弱电电缆 |
| `strong_cable` | 强电电缆 |
| `encoder` | 编码器线 |
| `other` | 其他 |
| `cable` | 历史兼容值，系统标准化为弱电电缆 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `Name` | 支持按名称查询和排序 |
| `Type` | 支持按分类查询和排序 |

业务规则：

- 新增和更新时通过 `PipeTypeCategory.Normalize` 标准化分类。
- 删除时如果被模块引用，控制器返回 `409 Conflict`。
- 启动初始化会删除历史水管数据：`Type = water` 或名称包含“水管”。

### 5.2 PipeModules

用途：保存可复用管线组合。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 模块 ID |
| `Name` | `TEXT` | 必填，最大 200 | 模块名称 |
| `Description` | `TEXT` | 最大 500 | 模块说明 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `Name` | 支持按名称查询和排序 |

业务规则：

- 模块名称保存前会执行 `Trim()`。
- 模块必须至少包含一条有效管线明细。
- 删除模块时级联删除模块明细。

### 5.3 PipeModuleItems

用途：保存模块内包含的管线和数量。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 明细 ID |
| `PipeModuleId` | `INTEGER` | 外键 | 所属模块 ID |
| `PipeTypeId` | `INTEGER` | 外键 | 管线 ID |
| `Qty` | `INTEGER` | 非空，默认 1 | 模块内数量 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `PipeModuleId` | 支持按模块加载明细 |
| `PipeTypeId` | 支持检查管线引用 |

外键：

| 字段 | 引用 | 删除行为 |
| --- | --- | --- |
| `PipeModuleId` | `PipeModules.Id` | Cascade |
| `PipeTypeId` | `PipeTypes.Id` | Restrict |

业务规则：

- 保存模块时，后端会过滤 `PipeTypeId <= 0` 或 `Qty <= 0` 的项。
- 同一模块内重复的 `PipeTypeId` 会合并数量。
- 保存前校验引用的管线 ID 必须存在。

### 5.4 WzlCatalog

用途：保存沃德 WZL 拖链型录。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 型录 ID |
| `Model` | `TEXT` | 必填，最大 50 | 型号 |
| `Function` | `TEXT` | 最大 30 | 功能，例如 `S:標準款` |
| `Stroke` | `TEXT` | 最大 20 | 适用行程 |
| `InnerHeight` | `decimal(8,2)` | 非空 | 内高 |
| `InnerWidth` | `decimal(8,2)` | 非空 | 内宽 |
| `OuterHeight` | `decimal(8,2)` | 非空 | 外高 |
| `OuterWidth` | `decimal(8,2)` | 非空 | 外宽 |
| `MinRadius` | `decimal(8,2)` | 非空 | 最小 R |
| `RecRadius` | `decimal(8,2)` | 非空 | 推荐 R |
| `ReservedK` | `decimal(8,2)` | 非空 | 预留 K |
| `BendLength` | `decimal(8,2)` | 非空 | 弯曲长度 Lp |
| `MountingH1` | `TEXT` | 最大 50 | 安装高度 H1 |
| `InterferenceH2` | `TEXT` | 最大 50 | 干涉高度 H2 |
| `InnerArea` | `decimal(10,2)` | 可空 | 内空面积 |
| `AppPipes` | `TEXT` | 最大 200 | 适用管线 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `Model` | 支持按型号查询 |
| `Function` | 支持按功能筛选 |

计算使用规则：

- 拖链 WZL 计算只使用 `Function = "S:標準款"` 且 `InnerArea != null` 的记录。
- `BendLength` 用作 Lp。
- `RecRadius` 用作弯曲半径校验。
- `InnerArea` 用作内空面积校验。

### 5.5 MeCatalog

用途：保存犸幕 ME 拖链型录。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 型录 ID |
| `BaseModel` | `TEXT` | 必填，最大 50 | 基础型号 |
| `FunctionSelect` | `TEXT` | 最大 50 | 功能选择 |
| `InnerHeight` | `decimal(8,2)` | 非空 | 内高 |
| `InnerWidth` | `decimal(8,2)` | 非空 | 内宽 |
| `R1` | `decimal(8,2)` | 非空 | 第一档弯曲半径 |
| `R2` | `decimal(8,2)` | 非空 | 第二档弯曲半径 |
| `R3` | `decimal(8,2)` | 非空 | 第三档弯曲半径 |
| `R1Suffix` | `TEXT` | 最大 10 | R1 后缀 |
| `R2Suffix` | `TEXT` | 最大 10 | R2 后缀 |
| `R3Suffix` | `TEXT` | 最大 10 | R3 后缀 |
| `Lp1` | `decimal(8,2)` | 非空 | R1 对应 Lp |
| `Lp2` | `decimal(8,2)` | 非空 | R2 对应 Lp |
| `Lp3` | `decimal(8,2)` | 非空 | R3 对应 Lp |
| `MountingH1` | `TEXT` | 最大 50 | 安装高度 H1 |
| `InnerArea` | `decimal(10,2)` | 非空 | 内部面积 |
| `MaxWeight` | `decimal(10,2)` | 非空 | 最大重量 |
| `SpanBase` | `decimal(10,2)` | 非空 | 架空基准 |
| `SpanSlope` | `decimal(10,4)` | 非空 | 架空斜率 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `BaseModel` | 支持按基础型号查询 |

计算使用规则：

- 每条 ME 记录展开为 R1、R2、R3 三个候选。
- 候选型号为 `BaseModel + R 后缀`。
- `Lp1/Lp2/Lp3` 分别对应候选 Lp。
- `SpanBase`、`SpanSlope`、`MaxWeight` 用于架空能力计算。

### 5.6 TrunkingCatalog

用途：保存线槽型录。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Id` | `INTEGER` | 主键 | 型录 ID |
| `Model` | `TEXT` | 必填，最大 50 | 线槽型号 |
| `Width` | `decimal(8,2)` | 非空 | 宽 |
| `Height` | `decimal(8,2)` | 非空 | 高 |
| `CrossSection` | `decimal(10,2)` | 非空 | 截面积 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `Model` | 支持按型号查询 |

计算使用规则：

- 线槽计算按 `CrossSection` 升序匹配。
- 推荐项为满足所需面积的最小截面积线槽。

### 5.7 AppSettings

用途：保存系统级设置。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `Key` | `TEXT` | 主键，最大 100 | 设置键 |
| `Value` | `TEXT` | 必填，最大 500 | 设置值 |

索引：

| 索引字段 | 说明 |
| --- | --- |
| `Key` | 唯一索引 |

当前设置项：

| Key | Value | 说明 |
| --- | --- | --- |
| `TrunkingFillRatioLimit` | `0` 到 `1` 的小数 | 线槽有效利用率上限 |

业务规则：

- 有效利用率使用 InvariantCulture 保存，避免区域格式导致解析失败。
- 非法值读取时回退默认 `0.60`。

## 6. DbContext 设计

文件：

```text
DragChain.API/Data/DragChainDbContext.cs
```

DbSet：

```csharp
public DbSet<PipeType> PipeTypes => Set<PipeType>();
public DbSet<WzlCatalog> WzlCatalog => Set<WzlCatalog>();
public DbSet<MeCatalog> MeCatalog => Set<MeCatalog>();
public DbSet<TrunkingCatalog> TrunkingCatalog => Set<TrunkingCatalog>();
public DbSet<PipeModule> PipeModules => Set<PipeModule>();
public DbSet<PipeModuleItem> PipeModuleItems => Set<PipeModuleItem>();
public DbSet<AppSetting> AppSettings => Set<AppSetting>();
```

模型配置：

- `PipeType`：索引 `Name`、`Type`。
- `WzlCatalog`：索引 `Model`、`Function`。
- `MeCatalog`：索引 `BaseModel`。
- `TrunkingCatalog`：索引 `Model`。
- `PipeModule`：索引 `Name`，配置模块与明细一对多，删除模块级联删除明细。
- `PipeModuleItem`：索引 `PipeModuleId`、`PipeTypeId`，配置管线外键限制删除。
- `AppSetting`：`Key` 唯一索引。


### 7.2 SQLite 兼容修复

文件：

```text
DragChain.API/Data/SqliteSchemaCompatibility.cs
```

兼容逻辑：

- 如果 `MeCatalog` 缺少 `FunctionSelect`，执行 `ALTER TABLE` 补列。
- 如果 `MeCatalog` 缺少 `MountingH1`，执行 `ALTER TABLE` 补列。
- 如果 `TrunkingCatalog` 存在旧字段 `InnerWidth`、`InnerHeight`、`Material`、`Remarks`，则重建为当前表结构。

设计原因：

- SQLite 对修改列和删除列支持有限。
- 旧版本数据库可能存在与当前模型不一致的字段。
- 应用启动时自动修复，减少部署升级成本。

## 9. 重置数据设计

方法：

```text
CatalogSeeder.ResetAsync(context)
```

当前逻辑：

1. 删除 `PipeTypes`。
2. 删除 `WzlCatalog`。
3. 删除 `MeCatalog`。
4. 删除 `TrunkingCatalog`。
5. 保存。
6. 重新执行 `SeedAsync`。

注意：

- 当前各控制器的 `reset` 接口都调用同一个 `ResetAsync`。
- 因此从管线库、WZL、ME 或线槽页面触发重置，实际会重置多类基础数据。
- `AppSettings` 不在当前重置逻辑中删除。

## 10. ID 生成策略

当前控制器新增数据时使用：

```csharp
var maxId = await table.MaxAsync(x => (int?)x.Id) ?? 0;
Id = maxId + 1;
```

涉及表：

- `PipeTypes`
- `PipeModules`
- `WzlCatalog`
- `MeCatalog`
- `TrunkingCatalog`

说明：

- 虽然 SQLite 主键可自增，当前代码仍手动设置 ID。
- 删除记录后再次新增会使用当前最大 ID 加 1。

## 11. 数据完整性约束

### 11.1 管线删除约束

控制器在删除管线前检查：

```text
PipeModuleItems.Any(item => item.PipeTypeId == id)
```

如果存在引用，返回：

```text
409 Conflict
```

### 11.2 模块保存约束

模块保存前校验：

- 至少存在一条 `PipeTypeId > 0 && Qty > 0` 的明细。
- 所有关联管线必须存在于 `PipeTypes`。
- 重复管线合并数量。

### 11.3 有效利用率约束

保存有效利用率时校验：

```text
0 < FillRatio <= 1
```

不满足则返回 `400 BadRequest`。

## 12. 备份与恢复建议

SQLite 数据库是单文件，建议部署时：

- 定期备份 `dragchain.db`。
- 如果存在 WAL 模式文件，也一并备份：
  - `dragchain.db-wal`
  - `dragchain.db-shm`
- 发布新版程序前先备份数据库。
- 不要用发布包中的数据库覆盖生产数据库。

## 13. 设计限制

- 没有审计表，无法追踪谁修改了数据。
- 没有计算历史表，无法恢复历史选型结果。
- WZL 架空参数未数据库化，修改需要改代码。
- 重置接口粒度较粗，会重置多类基础数据。
- SQLite 适合当前内网小规模数据，不适合作为高并发多用户编辑数据库。
